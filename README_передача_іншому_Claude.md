## Що вирішено щодо структури (як у Kids)

- «Оплати»: колонки A ID оплати, B ID студента, C ПІБ, D дата, E сума, F тариф (як у джерелі), G тариф (актуальна назва), H кількість, I початок, J завершення, K остання оплата?, L дата точна?, M впевненість, N джерело, O примітка, P:R формули періоду. Формули точно скопіювати з Kids «Оплати»!P2:R2 (`=IF(J2<>"";"";IF(OR(AND(E2<>"";E2>0;E2<=1500);F2="Бронь";F2="Інше");"бронь / застава";"період невідомий"))` і дві формули «Початок/Кінець без перекриття», див. у зразку). «Аналітика» теж формулами з зразка (посилання `'Учні'!` замінити на `'Студенти'!`).
- «Студенти»: ID, ПІБ (як у Kommo; порядок імені/прізвища не визначений), ID Kommo, ID PlanFix, ДН, країна, телефон, пошта, Telegram, sales/support менеджер, наставник, поточний тариф, статус навчання, етап угоди, курс, рівень, примітка.
- Правила з Kids: оплату-підсумок пакета обнуляти як дубль; бронь (≤1500 грн, «Бронь», «Інше») не дає оплаченого періоду; повернений студент це одна картка; тарифи на актуальні назви; дублі обнуляти з приміткою, не видаляти; «Остання оплата?» «так» тільки на останній оплаті; дати писати серійним числом з форматом `dd.mm.yyyy`; спірне в «Кейси для менеджерів».
- Правила LTV із зустрічі (Loom): не рахувати повернення за особистими обставинами, навчальних співробітників, сертифікатників без покупки; індиви від 20 уроків у LTV вручну; рестарт як окремий сценарій; неоплачені Ч/О. Колонки ознак: `враховується в LTV`, `причина виключення`, `рестарт-дата`.
